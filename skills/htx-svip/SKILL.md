# HTX SVIP 视觉

独立完成 HTX SVIP 黑金尊享物料。SVIP 是独立视觉体系，不修改或继承普通 `htx-brand` 的蓝白版式规则。

## 工作流

1. 逐字锁定源文案、金额、币种、时间、时区、等级、比例、排名、计算公式和二维码，不增写或改写。所有可见文案必须直接来自源文案，或是源文案的准确翻译；禁止为了版式、装饰或营销感自行增加标签、缩写、口号、说明和提示语。
2. 按真实内容确定画布高度。普通 KV 可用 1080×1080 或 1080×1280；活动长图和权益长图固定 1080px 宽，高度随内容增长。
3. 配图先查 Figma VIP 配图库并复用匹配素材；无合适素材时，再连接即梦等生图工具生成 KV 图像层。文字、品牌元素和业务信息不得交给生图模型。
4. 使用 HTML/CSS、SVG、Figma 或同类可控排版方式完成全部内容层并导出 PNG。用户要求时交付可编辑 SVG。
5. 渲染后检查真实像素、字体、裁切、溢出、表格列、二维码和多语言换行；发现问题后针对性修正并再次检查。

## 视觉语言

- 气质：高端、克制、稀缺、可信；避免赌场感、夸张奢侈品感和廉价金属光效。
- 主色：黑 `#000000`、炭黑卡片 `#171717`、暖金 `#D9AF62`、奶油白 `#F4E6CC`。当前 VIP Logo 使用已批准的灰底白色火焰版本；不再默认沿用普通 HTX 蓝底 Logo。
- 典型结构：“浅色 KV 头图 + 黑色信息正文”。KV 可使用暖米白到浅蓝的空气感渐变；正文靠轻微明度差分层，不堆叠描边、发光或重阴影。山体、岩层等收尾装饰不是默认结构，仅在源稿包含、用户明确要求或确有内容承接需要时使用。
- 主要意象：金属火焰、山峰、轨道、币面或抽象尊享徽记。金属偏香槟金、拉丝金或金白双色，不使用高饱和土豪金。

## KV 与即梦

- 即梦只生成场景底图或独立主体，如金属火焰雕塑、山体、币面、轨道、云雾和材质氛围。
- 提示词必须包含：无文字、无字母、无数字、无 Logo、无二维码、无水印；为标题预留明确负空间；主体轮廓完整；背景可延展；光源方向明确。
- 所有标题、副标题、金额、活动期、HTX Logo、SVIP 标识、规则、表格、CTA 和二维码必须后期排版，禁止让生图模型渲染。
- 若品牌火焰轮廓无法保证准确，生成“抽象双火焰金属雕塑”，最终再叠加官方 Logo；不得把 AI 近似图形当作官方标志。
- 优先生成透明主体或易抠图的浅色背景版本；主体四周至少保留约 10% 安全裁切余量。

## 长图结构

按内容选择模块，不要求每张都包含全部结构：

1. KV：Logo、主标题、源文案明确提供的利益点；生成主体或配图是可选项，不得为了填满右侧空间自行添加占位图形、示意币、字母徽章或装饰主体。期数或标签只有在源文案将其作为独立字段提供时才出现，不能从标题中自行提炼、缩写或重复生成。1080px 宽长图中通常占首屏约 520–850px；文字区和主体区不得互相侵入，未使用配图时保留有意图的留白并重新平衡文字区。
2. 基本信息：活动时间、参与资格、报名条件。使用纯文字或轻分隔线，不做厚重卡片。
3. 核心机制：按“一个活动或一类权益 = 一个模块”拆分。交易额、奖励、返现率等需要精确比较时使用表格或两列数据。
4. 权益目录：内容较多时使用两列卡片网格；每张卡片只放图标、权益名和短说明，同组卡片保持统一内边距、标题基线、说明行高和圆角。
5. 报名区：二维码仅在源内容包含或用户明确要求时出现；保留白底和完整静区，配短 CTA。
6. 收尾：默认使用干净的纯色、渐变或留白结束。低对比山体、岩层等背景元素仅在源稿包含或用户明确要求时使用，且不得压住二维码、CTA 或 Logo。

## 信息与表格

- 黑色正文中的主标题优先白色，模块标题和关键金额使用暖金，辅助说明使用中灰。对比不足时提升文字明度，不使用描边补救。
- 短文案并列卡片的文字块上下居中、左对齐，上下内边距相等；使用自动布局居中，并核对实际文字框高度与渲染结果，不能用过小文字框制造假居中。多行表格与长文卡片仍按内容采用顶部对齐。
- 独立配图完整显示，采用等比适配并保留安全边距；与 Logo、标题各自分区，不重叠。
- 活动卡片从 `#171717` 起调，1080px 画布圆角约 24–32px。卡片间距明显大于卡片内部行距。
- 同组活动卡片的左右与底部内边距必须统一；调整字号或行高后应同步增加卡片高度。1080px 长图中，最后一行数据到底板边缘建议保留约 48px，不得贴底、越界或仅靠裁切隐藏。
- 表格保持真实列结构。金额、比例、排名和门槛按列对齐；同一列不混用居中和左对齐。表头与数据之间使用低对比细线。
- 1080px 活动长图的表格数据优先使用约 26px 字号与 160% 行高，避免密集堆叠；英文表头通常不低于 24px。若已批准源稿使用文字渐变，数据列应复用其渐变方向与色阶（典型为白到浅奶油金），不得擅自简化为纯白；模块标题仍可使用纯暖金。
- 长文说明放在表格前后，不塞进数据单元格。不同语言版本允许高度变化，不压缩字号或行距强行等高。
- 权益长图可使用两列卡片；俄语等语言显著变长时可改为单列或增加卡片高度。

## 品牌、字体与资产

- 2026-11-05 用户批准的新 VIP Logo：[Figma 1710:409](https://www.figma.com/design/7mCMRqTdCl8fKM5xxTmkdO/Codex?node-id=1710-409)，原尺寸 100×100，深灰圆底 **#363534**、近白火焰（SVG 导出 **#FAFAFA**）。优先克隆原节点以保留精确填充；离线使用 `assets/htx-vip-logo-approved-100.svg`。它是当前 VIP 的默认版本，覆盖下述通用回退规则；不要自行改成蓝底、金色或拼装替代。

- Logo 优先直接复用用户指定设计稿或同一项目中已经批准的完整 Logo 组合，保留其图形、中文字标、比例、间距和颜色，不自行重绘或用近似文字拼装。没有可复用的已批准组合时，才使用本 skill `assets/` 内的官方 HTX Logo。浅色 KV 使用深色 Logo，黑色正文使用反白 Logo；没有已批准版本时不得把 Logo 改成金色。
- 2026-11-05 最新规范：所有语言强制使用鸿蒙 HarmonyOS Sans SC，英文也使用鸿蒙，不再使用 Urbanist；只用 400/500/700 字重，不使用 800、900、Black、斜体或拉伸字体。
- 1080px 宽的长图中，任何可读文字的字号不得低于 22px；标签、表头、辅助说明、时间、资格、二维码提示和脚注也必须遵守。内容放不下时增加模块或画布高度，不得缩小字号规避。
- 标签是可选结构，不是 SVIP 的固定元素。仅当源文案明确提供独立标签内容时才使用；不得自行创造 `SVIP`、期数、身份、资格或营销短语标签，也不得把标题内容缩写后重复放进标签。

## 质检

- KV 中不得残留伪文字、伪 Logo、水印或畸形符号。
- 所有业务数字和源文案逐字一致，不用 AI 生成内容填补缺失信息。
- 对照源文案检查每一处可见文字；任何无法在源文案中找到对应内容的标签、口号、说明或提示都必须删除。
- 检查全部文本字体是否为 HarmonyOS Sans SC，包含英文、数字、日期与 CTA。
- 检查 Logo 是否直接来自用户指定或项目内已批准的资产；不得用自行拼装版本替代可复用的原始组合。
- 检查 Hero 是否存在无内容依据的右侧配图或占位元素，检查底部是否存在未经要求的山峰、岩层等背景装饰；有则删除并重新调整留白与视觉重心。
- 检查 1080px 长图的最小字号不低于 22px。
- 对照源稿检查表格数据的字号、行高和文字填充；不得遗漏源稿已明确使用的文字渐变。
- 检查每张同组卡片最后一行到底板边缘的距离，确保底部内边距一致且内容完全落在卡片内部。
- 二维码可扫码且静区完整；表格列不串位；中英俄等语言不裁切；浅色 KV 与黑色正文转场自然。
- 尊享感来自材质、比例与留白，不来自大面积金色、发光、噪点或多重阴影。
- SVG 必须保持文字、形状、渐变和 Logo 分层可编辑；禁止用整张 PNG 或 `foreignObject` 伪装可编辑结构，并用 `xmllint --noout` 验证。
